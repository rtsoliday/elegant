```sh
./test/gpu_cuda/production_smoke.sh --label-prefix phase11
```

Phase 18 profile wrappers include the SCMULT pair `scRing2` and `scRing2_no_watch`, the ion/Poisson wrapper `ionEffectsPoisson`, plus the field-map and wiggler wrappers `bmapxy1`, `bmxyz1`, `boffaxe1`, `cwiggler10`, `uKickMap1`, `latticeErrors6`, `latticeErrors6_loss_output`, and `latticeErrors6_global_loss`. Use `scRing2_no_watch` to quantify WATCH synchronization cost without changing the source production lattice.  It disables WATCH diagnostics through `&alter_elements`, so `.w1` output is intentionally absent while the common physics outputs should remain comparable.  The May 7, 2026 Phase 18 thin-RFCA measurement reduced normal no-WATCH CUDA sync accounting to one RFCA setup request plus deallocation and ran the 601-pass case in 22.69s, versus 22.86s for standard `scRing2` with WATCH output enabled.  The May 9, 2026 action-8 quick refresh with `ELEGANT_GPU_ENABLE_SCMULT=1` matched all 5 common SDDS files at `1e-11`, reported 8 resident `SCMULT` kernels and no CPU-element fallback, and had only final `gpuBaseDealloc` synchronization; report: `test/gpu_cuda/output/reports/action8-scmult-no-watch-quick.md`.

Use `bmapxy1`, `bmxyz1`, `boffaxe1`, and `cwiggler10` as bounded field-map and wiggler fallback comparison wrappers.  The May 9, 2026 action-8 refresh matched all 19 common SDDS files at `1e-11`; CUDA reported the expected CPU-owned `BMXYZ` and `CWIGGLER` handoffs plus 10 read-only `WATCH parameter output` synchronizations from `cwiggler10`, with no resident field-map/wiggler kernels.  Reports: `test/gpu_cuda/output/reports/action8-fieldmap-wiggler-fallback-refresh.md` and `test/gpu_cuda/output/reports/action8-fieldmap-wiggler-fallbacks.md`.

Use `uKickMap1` to exercise the narrow deterministic `UKICKMAP` CUDA prototype against the production kick-map SDDS file.  The May 7, 2026 timing gate matched all 4 common SDDS files at `1e-11` and, after device map-array caching, ran the 30,000-particle, 2,000-pass workload in 13.58s on `gpu-elegant`, versus 55.43s on CPU.  The May 9, 2026 action-8 map-loss gate added opt-in resident stable compaction through `ELEGANT_GPU_ENABLE_MAGNET_LOSS_COMPACTION=1`: the 3,000-particle, 2,000-pass slice matched CPU at `1e-11`, ran in 1.82s versus 5.54s CPU, and reduced the same workload's 101 `UKICKMAP particle loss fallback` syncs to only final `gpuBaseDealloc`; report: `test/gpu_cuda/output/reports/action8-ukickmap-map-loss-compaction.md`.

Use `latticeErrors6` as the high-count production-shaped `UKICKMAP` compaction gate.  It repeats ten production septum-map files four times per pass, so the 30,000-particle, 2-pass action-8 run exercised 80 `UKICKMAP` tracks with intentional no-`.los` map loss.  With `ELEGANT_GPU_ENABLE_MAGNET_LOSS_COMPACTION=1`, the GPU run matched all 4 common SDDS files at `1e-11`, kept 564 survivors, ran in 0.41s versus 0.77s CPU, and synchronized only at final `gpuBaseDealloc`; the same GPU workload without compaction still matched CPU but requested 80 `UKICKMAP particle loss fallback` synchronizations and ran in 0.92s.  Reports: `test/gpu_cuda/output/reports/action8-latticeErrors6-map-loss-compaction.md` and `test/gpu_cuda/output/reports/action8-latticeErrors6-map-loss-fallbacks.md`.

Use `latticeErrors6_loss_output` and `latticeErrors6_global_loss` as the high-count production-shaped `UKICKMAP` loss-row fallback guards.  They repeat the same ten production septum-map files four times per pass, but request `.los`/`.acc` output, with the global-loss wrapper also enabling `losses_include_global_coordinates=1`.  With `ELEGANT_GPU_ENABLE_MAGNET_LOSS_COMPACTION=1`, the 3,000-particle, 2-pass CPU/GPU quick runs matched all 12 common SDDS files at `1e-11`, including `.los`; CUDA reported 73 `UKICKMAP particle loss fallback` synchronizations per case, proving host loss-row semantics remain explicit CPU fallback.  Reports: `test/gpu_cuda/output/reports/action8-ukickmap-loss-output-fallback.md` and `test/gpu_cuda/output/reports/action8-ukickmap-loss-output-fallbacks.md`.

Use `ionEffectsPoisson` as the small ion-effects/Poisson fallback gate before any cuFFT-backed `poisson.cc` work.  It is synthetic because the local production test set has no `IONEFFECTS` or `BEAMBEAM` deck, but it includes the production-like input surface: `CHARGE`, pressure-profile SDDS data, ion-property SDDS data, positive ion spans, and a 16x16 Poisson grid.  The May 9, 2026 action-8 quick run matched all 4 common SDDS files at `1e-11`; CUDA reported the expected `CPU element: IONEFFECTS` fallback twice, one short-GPU-island skip, and final `gpuBaseDealloc` synchronization.  Reports: `test/gpu_cuda/output/reports/action8-ion-effects-poisson-fallback.md` and `test/gpu_cuda/output/reports/action8-ion-effects-poisson-fallbacks.md`.
